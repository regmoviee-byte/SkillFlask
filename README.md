# Skill Flask

Персональный трекер развития навыков. Выполненные действия приносят очки, очки заполняют колбы, каждая заполненная колба — новый уровень. Требования: `Skill Flask — требования к персональному MVP v0.2`.

Приложение мобильное: Telegram Mini App и мобильный браузер, дальше — нативное приложение. Десктоп не поддерживается специально.

## Что умеет первый срез

Цепочка «навык → действие → очки → колба → веха → завершение» (раздел 13 требований):

- вкладка «Сегодня» — стартовый экран, как только у активного навыка есть хотя бы одно действие (иначе приложение открывается на «Навыках»): дата, плитки «Сегодня» (очки за день и семь точек недели с понедельника — активный день закрашен, сегодня обведено, без цели и без счёта пропусков) и «Действий», действия всех активных навыков по группам с кнопкой очков в одно нажатие, кнопка-календарь «Задним числом» у каждой группы, «Сделано сегодня» (одна строка на действие с «×N», отменённые — зачёркнуты; строка открывает лист «Выполнение»). Расписаний пока нет, поэтому ничего не «планируется» и ничего не бывает просрочено: день содержит только то, что в нём сделано. Порядок — недавно использованные навыки и действия сверху, но пока экран открыт, строки не переезжают под пальцем. Одна подсказка на всё приложение — над первой кнопкой «Сегодня», до первого нажатия;
- главная «Навыки» как мотивационная панель: плитки «Сегодня» (ведёт на «Сегодня»), «Заполнено» (все заполненные колбы) и «Последняя ачивка» (до первой — «Следующая» с прогрессом; веха, достигнутая позже последней ачивки, — второй строкой); карточки навыков с кольцом и номером колбы, «42 / 100», полосой жидкости, точками вехи, лавровой меткой «веха достигнута» и «+12 сегодня»; активные — по последней активности; фильтр «Активные · Достигнутые · Архив» появляется, когда непустых групп хотя бы две, и показывает только их (выбранная группа хранится в адресе, `#/skills?filter=archived`, поэтому «Назад» с карточки возвращает в неё); пустое состояние с примером «Английский B1 → C1»;
- жизненный цикл навыка (раздел 6): «Архивировать навык» в форме навыка, «Продолжить с этого места» и «Начать заново» у архивного, «Начать заново» у достигнутого (см. ниже);
- создание навыка с подписями «сейчас → цель», вехой (по умолчанию 10 колб) и ёмкостью колб;
- действия типа «выполнено / нет» с фиксированными очками; их можно переименовать, изменить очки (прошлое не пересчитывается) и убрать из списка — история остаётся;
- отметка в одно нажатие на «Сегодня» или в два через экран навыка: кнопка «+5» у действия; очки улетают в колбу, тост «+5 · Чтение» с кнопкой «Отменить» держится 6 секунд; отметка задним числом — отдельный экран «Задним числом»;
- экран навыка — «герой»: колба 140 px с волной, делениями в очках и свечением, крупный номер колбы, «42 / 100», «42% · ещё 58 до колбы 4», «Всего …»; полка мини-колб до вехи (при цели больше 12 — полоса); у достигнутого навыка — золотая колба с пробкой;
- моменты награды без оверлеев и конфетти: заполнение колбы — подъём, перелив через край, слив и наполнение остатком прямо в колбе (до трёх сжатых циклов, если заполнилось несколько колб), пилюля «Колба 3» и сильная вибрация; если колбы нет на экране — карточка сверху; веха — нижний лист «Завершить навык / Продолжить развитие / Решу позже»; завершение — золото и пробка;
- отмена, возврат и коррекция выполнения — новые строки журнала, а не удаление; лист «Выполнение» из истории: заметка, «Отменить выполнение» (с подтверждением) и «Вернуть»;
- перенос остатка очков в следующую колбу, несколько колб за одно выполнение;
- достижение вехи и выбор «Завершить» / «Продолжить»;
- история — лента по дням («Сегодня», «Вчера», дата) с разделителями «Колба 2 заполнена», «Возврат к колбе 1», «Веха «…» достигнута», «Навык достигнут», состоянием колбы после каждой операции и подгрузкой по 20 операций; события выводятся из журнала, а не хранятся;
- форма навыка в два уровня: название и «Сейчас → Цель» с превью вехи, остальное — в «Дополнительно»; на пустом навыке три примера действий подставляют название и очки;
- редактирование и полное удаление навыка;
- резервная копия: автокопия в облаке Telegram (через 30 секунд после изменения и при уходе в фон), предложение восстановить её при пустом запуске, файл JSON для браузера и второго экземпляра, загрузка копии с предпросмотром;
- «Настройки»: данные и копии, «Меньше анимации», «Виброотклик», версия, «Обновить приложение», активные дни за 14 дней, журнал последних ошибок, «Удалить все данные»;
- ачивки (см. ниже): 7 лестниц с 33 ступенями и 11 значков, вкладка «Ачивки» со сводкой, фильтром «Все · Получено · Впереди», карточками лестниц, плитками значков и листом подробностей, точка «новые» на вкладке, карточка «Новая ачивка» сверху экрана.

Расписания действий и «Сегодня» v2 с «Осталось» — следующий этап.

## Стек

- React + TypeScript + Vite;
- IndexedDB через Dexie — данные хранятся локально на устройстве;
- Vitest + fake-indexeddb для тестов.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173, доступен и с телефона в той же сети
npm test           # unit- и интеграционные тесты
npm run build      # сборка в dist/
npm run check-bundle  # бюджет: gzip JS в dist/assets ≤ 173 КБ (проверяется в CI)
npm run screenshots   # прогон по экранам на телефонном viewport (нужен npm run preview); DARK=1 и TG_THEME=purple — тёмная и фиолетовая тема Telegram
npm run seed       # подсказка, как заполнить dev-базу демо-данными
```

Галерея компонентов (токены, типографика на 100 % и 130 %, листы, тосты, скелетоны, пустые состояния, иконки, граница ошибок) — маршрут `/styleguide`, только в dev-сборке; скрипт скриншотов снимает её, если запущен против `npm run dev`. Ручные проверки на устройствах — `docs/qa-checklist.md`.

Демо-данные: запустить `npm run dev`, открыть приложение и в консоли браузера вызвать `__skillFlask.seed()` (или `__skillFlask.seed({ days: 45, seed: 7 })` — число дней истории и зерно генератора). Создаются три навыка с действиями и выполнениями через обычные сервисы, так что журнал остаётся корректным. Dev-сервер работает с базой `skill-flask-dev`, боевая база `skill-flask` не затрагивается.

Ключевые решения:

- Прогресс не хранится одним числом: это сумма операций `PointTransaction`, уровень всегда пересчитывается из журнала.
- `StepCompletion` хранит снимок настроек шага, поэтому изменение шаблона не меняет прошлое.
- Ёмкость колбы: сначала «свои значения», затем линейный рост `база + прирост × (n − 1)` (по умолчанию 100, 150, 200…).
- Завершённый навык доступен только для чтения. Если активный навык оказался ниже вехи, веха снова становится недостигнутой.
- Очки хранятся с одним знаком после запятой, а складываются как целые десятые (`toDeci`/`fromDeci`), поэтому `99,9 + 0,1` заполняет колбу на 100 ровно.
- Моменты награды (колба, TopCard, лист вехи) запускаются только результатом записи в этой сессии (`orderCelebrations(result, …)`), никогда разницей живых запросов: при открытии экрана ничего не анимируется. Перед записью экран «придерживает» показанный прогресс, чтобы очки сначала долетели до колбы, и отпускает его, когда колба доиграла.

## Ачивки

Всё считается из журнала чистой функцией `evaluateAchievements(snapshot)` (`src/domain/achievements/`): снимок шести таблиц (навыки, вехи, ёмкости, действия, выполнения, операции) превращается в один поток событий — «навык создан», «действие создано», операция журнала с состоянием колбы до и после, «навык завершён», — упорядоченный по времени записи, и прогоняется через накопитель `Stats`. Ачивка получена, если её правило `value(stats) >= target` верно на конце истории.

- **Правило дат.** `unlockedAt` — время события, при котором правило в последний раз стало верным. Отметка задним числом получает ачивку в момент записи, а не календарной датой выполнения; запись каталога, добавленная позже, открывается задним числом с исторической датой.
- **Отзыв.** Отмена выполнения, меньшая ёмкость колб или удаление навыка, убравшие основание, молча закрывают ачивку (как веха становится недостигнутой). Повторное получение датируется заново и празднуется снова. Отменённое выполнение не считается ни в днях, ни в количестве, но его строки `+` и `−` по-прежнему двигают колбы.
- **Ничего против пользователя.** Нет «текущей серии» (лестница «Лучшая серия» — только рекорд), наград за вход, время суток, календарные даты или возвращение после перерыва; нет бонусных очков и секретов; редкость (бронза, серебро, золото) — только цвет.
- **Журнал показанного.** Таблица `achievementUnlocks` — не источник истины: строка есть, пока ачивка получена; `celebratedAt` ставится, когда показана карточка, `seenAt` — через 800 мс после открытия вкладки (гаснет точка на вкладке). `syncAchievements(now)` сверяет её с движком внутри транзакции каждой записи (выполнение, отмена, возврат, коррекция, навык, действие, их изменение, архив, «Начать заново», завершение, удаление) и один раз при старте. Получено этой записью — если дата не раньше её `now`; такие ачивки мутация возвращает в `MutationResult.achievements` (записи без него — новый навык или действие, завершение навыка — публикуют их через `onAchievementsEarned`), и `CelebrationProvider` показывает карточку «Новая ачивка». Всё более старое (правка ёмкостей, новая запись каталога) появляется тихо, с точкой на вкладке. При старте ничего не празднуется.
- **Карточка** — вариант TopCard под шапкой экрана: медаль поворачивается, 3,5 с, свайп вверх закрывает, тап открывает `#/achievements?focus=<id>` (плитка или лестница подсвечивается). Карточки идут своей очередью после колбы и листа вехи, с паузой 400 мс, не поверх листа; больше двух за одну запись — одна карточка «… и ещё N ачивки». Никаких оверлеев.
- **Изменение ёмкостей** переинтерпретирует журнал: лестница «Колбы», «Первая колба», «Ювелирно», вехи пересчитываются с историческими датами.
- **Резервная копия** содержит `achievementUnlocks` как есть, поэтому после восстановления праздники не повторяются; ачивки, которых в файле нет (старая копия без таблицы), записываются как уже показанные.
- **Скорость.** Проход по 5 000 выполнений — около 30 мс; вкладка и главная берут результат из кэша, пока не изменились малые таблицы или размер и последняя строка журнала.

Как добавить запись каталога: значок — объект в `BADGES` (`src/domain/achievements/catalog.ts`) с новым постоянным `id`, русскими `title`/`description`/`howTo`, редкостью, глифом (`MedalGlyph`, рисунок — в `src/ui/achievements/medals.tsx`) и правилом `value(stats)` (если нужного числа нет — добавить его в `stats.ts`); ступень — число в `tiers` лестницы. `id` нельзя переиспользовать или переименовывать: на него ссылаются журнал показанного и резервные копии. `catalog.test.ts` проверяет уникальность, цели, возрастание ступеней и тон текстов; при следующем старте или записи новая ачивка откроется задним числом.

## Жизненный цикл навыка

| Из | Действие | Результат |
|---|---|---|
| `ACTIVE` | «Архивировать навык» (форма навыка, с подтверждением) | `ARCHIVED`, `archivedAt`; навык пропадает с «Сегодня» и из активных, история и прогресс целы; пока навык в архиве, в истории есть событие «Навык в архиве» (оно выводится из `archivedAt`, поэтому после «Продолжить с этого места» пропадает) |
| `ARCHIVED` | «Продолжить с этого места» | тот же навык снова `ACTIVE` с прежним прогрессом; достигнутая веха остаётся достигнутой, «Завершить / Продолжить» возвращаются |
| `ARCHIVED`, `COMPLETED` | «Начать заново» (с подтверждением) | новый навык `ACTIVE` с тем же названием, подписями, ёмкостями, вехой (не достигнута) и действиями из списка (`scheduleFrom` = сегодня), пустой журнал, `originSkillId` → исходный; открывается его форма, чтобы переименовать или сменить цель. Исходный навык не меняется |
| любой | «Удалить навык» (форма активного навыка; внизу экрана архивного и достигнутого) | навык и вся его история удаляются; копия, сделанная «Начать заново», остаётся |

Архивный и достигнутый навыки доступны только для просмотра: действия нельзя отметить, добавить или изменить, настройки навыка (название, веха, ёмкости) — тоже, форма по адресу `/skills/:id/edit` возвращает на экран навыка (`Навык не активен`); заметку к выполнению менять можно.

## Правила журнала

- Строки `PointTransaction` никогда не редактируются и не удаляются. Любое изменение прогресса — новая строка со знаком и причиной: `COMPLETION`, `CORRECTION`, `CANCELLATION`, `RESTORE`.
- Жёсткого удаления выполнения нет, даже для «Отменить» сразу после отметки: отмена пишет `CANCELLATION` на сумму операций выполнения, выполнение остаётся в истории со статусом `CANCELLED` (зачёркнуто, «Отменено»); «Вернуть» пишет `RESTORE`; изменение минут временного выполнения — `CORRECTION` на разницу по снимку ставки. У завершённого навыка отмена и возврат запрещены, заметку менять можно — она не трогает очки.
- Повторная отметка того же действия за ту же дату в пределах 1,5 с отклоняется как двойное нажатие; интерфейс, кроме того, 600 мс показывает ✓ зелёной, а до конца этих 1,5 с (считая от нажатия) — приглушённой и не принимает повторные нажатия.
- Баланс сворачивается одним правилом `foldJournal`: после каждой операции сумма обрезается снизу нулём, так что `[5, −10, 5]` даёт 5 и на экране навыка, и в списке навыков.
- Порядок операций — `(createdAt, id)`; `nowIso()` строго возрастает в пределах сессии.
- Ёмкости колб — линейка, а не часть журнала: они не записываются в операции, и их правка переинтерпретирует всю историю (уровни и дата вехи пересчитываются).
- Дата достижения вехи выводится из журнала (`milestoneReachedAt`); `Milestone.reachedAt` — кэш. Правка цели вехи не переписывает историческую дату.
- Операция без выполнения (`completionId: null`) допустима только для `CORRECTION` (сейчас такие не пишутся); импорт копии проверяет это отдельно, иначе такая строка обошла бы проверку журнала.
- Инвариант, который проверяет `verifyJournal()` после каждого сервисного теста: у каждой операции есть навык и выполнение; сумма операций активного выполнения равна начисленным очкам, отменённого — нулю.
- Схема Dexie: номер версии только растёт и равен `schemaVersion` резервной копии; каждая версия добавляет поля со значениями по умолчанию в идемпотентном апгрейде (`src/data/migrations/`); первичные ключи и имена таблиц не меняются; булевы поля не индексируются. Перед первым апгрейдом с версии 1 снимок базы сохраняется в `localStorage['sf_premigration_v1']`.

## Тон и копирайт

Все строки интерфейса живут в `src/ui/copy.ts`; тест `copy.test.ts` проверяет словарь и исходники экранов и сервисов на запрещённые слова.

1. Термины: навык, действие, очки, колба, веха, ачивка. Никогда «баллы».
2. Запрещены: просрочено, пропущено, штраф, долг, провал, сгорела, потеряна, «не сдавайтесь», обратный отсчёт, красный цвет для дней без активности.
3. Прошлое описывается тем, что было («В этот день отметок нет», «Активных дней: 9»), а не тем, чего не было.
4. Квоты — прогресс к цели («1 из 3 на неделе»); «осталось» — только про сегодняшний план.
5. Сравнения — только когда в пользу пользователя.
6. Откат уровня — «Возврат к колбе N» в тостах и истории.
7. Восклицательные знаки и эмодзи — только в тосте «Навык достигнут 🎉». Веха встречает нижним листом «Веха достигнута», без эмодзи.

## Telegram Mini App

Чек-лист публикации:

1. Включить GitHub Pages: *Settings → Pages → Source: GitHub Actions*. После пуша в `main` workflow `CI` опубликует сборку (URL вида `https://<user>.github.io/<repo>/`).
2. [@BotFather](https://t.me/BotFather) → `/newbot`: имя и username бота.
3. `/newapp` → выбрать бота, заполнить название, короткое описание, фото 640×360, (GIF — пропустить), URL сборки и короткое имя (`short name`). Приложение открывается по ссылке `https://t.me/<bot>/<short_name>`.
4. *Bot Settings → Menu Button → Configure menu button*: тот же URL и подпись («Открыть») — кнопка слева от поля ввода в чате с ботом.
5. *Bot Settings → Configure Mini App*: включить Mini App, указать тот же URL (открывается из профиля бота).
6. Отдельный dev-бот (`/newbot` ещё раз, например `skill_flask_dev_bot`) с URL превью-сборки (ветка, тоннель к `npm run dev` по https). У каждого бота своё облако CloudStorage, так что тестовые копии не смешиваются с настоящими; dev-сборка к тому же работает с базой `skill-flask-dev`.
7. Бот не отвечает на сообщения и не нужен сервер: всё работает внутри Mini App.

Отладка: Telegram Desktop — *Settings → Advanced → Experimental → Enable webview inspection*, затем правый клик → «Inspect»; Android — включить *WebView debug* в настройках Telegram (долгое нажатие на номер версии в *Settings*) и открыть `chrome://inspect`; iOS — только вручную: журнал последних ошибок виден в «Настройки → О приложении → Ошибки».

Цвета берутся из темы Telegram (`--tg-theme-*`, переключение на лету по `themeChanged`; слишком тёмный или серый акцент заменяется фирменным цианом только для жидкости). Используются нативные кнопки «Назад», MainButton/SecondaryButton вместо HTML-футера, `showConfirm`/`showPopup`, подтверждение закрытия при несохранённой форме, вибро-отклик (выключатель «Виброотклик» в «Настройках» пишет `sf_haptics=off` в localStorage), safe-area и цвет нижней панели. Все вызовы SDK идут через `supports(version)` — таблица версий Bot API лежит в `src/platform/telegram.ts`.

## Резервная копия

Данные живут в IndexedDB на устройстве, а её внутри Telegram стирают «Очистить кэш», переустановка и iOS. Поэтому есть два вида копии; обе — **копия, а не синхронизация**: восстановление заменяет всё, что есть на устройстве, слияния нет.

- **Облако Telegram** (Bot API 6.9+, по умолчанию включено, выключатель в «Настройках»). Через 30 секунд после последнего изменения и сразу при уходе приложения в фон копия сжимается (gzip через `CompressionStream`, base64; без него — JSON в ASCII) и пишется в CloudStorage бота кусками по 4 000 символов: `sf_a_000…` или `sf_b_000…`, затем `sf_meta` = `{ v, at, n, len, h, enc, slot, schemaVersion, skills, completions }`, где `h` — первые 16 hex-символов SHA-256. Запись идёт в свободный слот, `sf_meta` — последним, старый слот удаляется после него: прерванное сохранение не портит предыдущую копию. Чтение проверяет число кусков, длину и хеш. Лимит — 500 кусков (≈ 2 МБ сжатых данных), больше — «сохраните файл». Автокопия никогда не заменяет облачную копию пустым журналом и заменяет только «свою» копию — ту, что это устройство последним сохранило или восстановило (её хеш хранится в настройке `cloudBackupHash`), или пустое облако. Чужую копию (с другого телефона, оставленную при «Удалить все данные», не предложенную из-за сбоя облака при запуске) автокопия не трогает: «Настройки» пишут «В облаке другая копия…», её можно восстановить, удалить или заменить кнопкой «Сохранить сейчас» после подтверждения. При запуске на пустой базе внутри Telegram приложение находит `sf_meta` и спрашивает: «Восстановить» или «Начать с чистого листа» — один раз, без тихого восстановления.
- **Файл** `skill-flask-YYYY-MM-DD.json` («Настройки → Скачать файл»): в браузере — скачивание; в Telegram — «Поделиться» файлом, иначе копирование текста в буфер (вставить в «Избранное»), иначе текст на экране. «Загрузить из файла…» принимает файл или вставленный текст, показывает, что в копии, и заменяет данные после подтверждения. В браузере через 7 дней после последней копии появляется напоминание.

Формат (`src/data/backup.ts`): `{ format: 'skill-flask-backup', schemaVersion, appVersion, exportedAt, installId, tables }`, где `tables` — строки всех таблиц Dexie как есть (включая `settings` и `achievementUnlocks`), ничего вычисляемого. `schemaVersion` равен версии Dexie; копия более старой схемы проходит те же чистые преобразования строк, что и апгрейд базы (`src/data/migrations/`), более новой — отклоняется. Перед импортом проверяются типы, даты, очки, уникальность ключей и ссылки (с путём поля: «Файл повреждён: completions[3].date»), после — инвариант журнала; при нарушении импорт целиком откатывается. Настройки, описывающие устройство (`installId`, отметки о копиях, «Меньше анимации»), при импорте остаются свои.
